# UX polish: working plan

Status: in progress. Do not mark the release ready until the remaining checks and a final review are complete. Work stays on the session branch; no main deployment is implied.

## Findings from initial code audit (7 November 2026)

- The home intake automatically opens the inspector. Its next steps navigate to empty tools, breaking the user's flow; text recommendations cannot load the inspected file at all.
- Suggestions based only on a broad MIME category can recommend tools that reject SVG/HEIC or a mismatched file. The ordinary tool catalogue should remain a separate, fresh-workspace path.
- Buttons use fixed height and no wrapping, making long labels vulnerable to overflow. User-provided names and other unbroken text need resilient wrapping. The homepage silently rejects empty files.
- Existing layout breakpoints and accessibility patterns exist, but need a real viewport and interaction audit rather than assuming CSS or unit tests prove visual quality.

### PDF editor implementation
- Added a beta local-first PDF editor at `/tools/pdf-editor/`, linked from the PDF category and compatible inspector suggestions with the selected-file handoff. It reorders/removes pages and queues additive text, JPEG/PNG images and filled rectangles. Placement uses numeric PDF coordinates, not drag-and-drop; the generated copy can be previewed using a lazily loaded PDF.js renderer and downloaded. The original remains untouched.
- PDF worker validates page indices, addition count, coordinates, image formats and budgets; built-in Helvetica character support is checked explicitly to avoid silently dropping unsupported scripts. Limits are 200 MB source, 500 pages, 100 additions, 10 MB per image and 50 MB total image input. The interface warns that overlays are not secure redaction and that page copying can lose interactive features, bookmarks and signatures. It does not edit existing text or interactive forms; password-protected files need unlocking first. Unusual PDF crop boxes/origins and rotated pages require particular care when positioning content.

### Existing-text editing / secure redaction decision
- The user chose to retain a strict no-loss guarantee for all supported PDFs rather than proceed with a limited form-field editor or investigate an AGPL/commercial redaction engine. Neither feature is implemented: the current `@cantoo/pdf-lib` documents that ordinary page text cannot be edited through its API, and drawing over content is not redaction. Redaction necessarily removes selected data and cannot guarantee unchanged document features for every PDF; a blanket guarantee cannot be established with the available engine and validation. MuPDF.js on npm is AGPL-3.0-or-later and was not added to this MIT project.
- Existing beta-editor page copying is separately subject to the warnings already shown about interactive forms, annotations, bookmarks and signatures; the original file remains unchanged. Do not describe it as lossless or secure redaction. Revisit only if the user revises the guarantee and a suitably licensed engine, explicit compatibility policy and independent security/round-trip validation are agreed.

### Inspector file comparison and PDF preservation follow-up
- The inspector still supports a single file, and now accepts one or two files at initial selection or an optional second file later. The comparison checks every byte and reports a match or the first differing zero-based byte offset, plus both SHA-256 digests. Names and timestamps do not determine equality; a match does not establish provenance or trust. Comparison reads and hashes in 1 MiB chunks, yields between chunks, allows cancellation and caps each file at 512 MiB; the first file is also subject to the inspector's existing 25 MiB text / 400 MiB other intake limits. It never uploads files. Empty files remain rejected by the existing file picker.
- Added unit tests for equal files, same-size modifications, differing lengths, SHA-256 cross-checks, chunk boundaries, progress, cancellation and size limits. Added an opt-in `npm run test:browser-inspector`; the built app passed single-file, optional second-file and initial two-file flows, matching and same-size-different cases at 320 and 1366 pixels. The previous PDF editor browser workflow also passed at both sizes.
- Improved PDF editor preservation without claiming universal losslessness: if page order is unchanged and no additions are made, output returns the original bytes exactly. Additions without page changes now use the loaded source document rather than copying pages into a new document, and avoid automatic form appearance rewriting. A round-trip test confirms an example text form field and title survive an add-only edit, and that a no-op preserves bytes. Other interactive features and signatures can still be altered or invalidated when saving; reordered/excluded pages still require copying and can lose document-level data. Existing warnings and the strict decision against general existing-text editing and secure redaction remain in place.
- `npm run verify` passed 505 unit tests, 60 DOM tests and 29 prerendered pages; both targeted browser checks passed and `git diff --check` passed. The routine, real-device, cross-browser and manual accessibility release checkpoints remain open; no push, merge or deployment.

### Excel-to-CSV addition
- Added a beta, local-first XLSX-to-CSV tool, linked in Archives & Office and offered as an inspector handoff for supported `.xlsx` files up to 10 MiB. Users select a sheet, preview values and download UTF-8 CSV; the source stays untouched. This is not PDF-to-Word or Word-to-PDF.
- The exporter intentionally has a limited scope: standard `.xlsx` only (not `.xls`), at most 50 sheets, 10,000 rows, 256 columns and 200,000 output cells. Compressed input is limited to 10 MiB and validated ZIP extraction to 24 MiB total / 8 MiB per entry. It refuses missing formula caches, error cells, invalid references, unsupported cell types and unsupported Excel escapes instead of silently fabricating values. Cached formula values may still be stale; dates and number formatting are not reconstructed, so date serials and raw numeric values are exported. CSV cannot retain other sheets, formatting, formulas, charts or merged-cell structure.
- Formula-like CSV values are apostrophe-prefixed by default, which changes values and is not guaranteed protection in every spreadsheet program. Raw export requires explicit acknowledgement. Tests cover sparse cell positions, exact numeric strings, quoting, missing formula results, cell errors, size bounds, and injection-related toggling. A real openpyxl-generated workbook was checked in Chromium, including refusal of an uncached formula and correct quoting when exporting a second sheet. The opt-in `npm run test:browser-xlsx` covers inspector handoff, sheet selection, error recovery and protected/raw downloads at 320 and 1366 pixels. Real Excel/LibreOffice interoperability and physical-device, cross-browser and manual accessibility testing remain open; this is not a fidelity guarantee.
