Image codec & batch-concurrency probe

Runs the same work the image tools do — decode a JPEG, downscale to 1600px, re-encode at q82 — first one item at a time, then two at a time. It reports wall time, peak memory, long tasks and event-loop lag, so the question “is a second batch lane worth it?” is answered by this machine rather than by an opinion.

Nothing is uploaded. The page loads no third-party resources. For performance.measureUserAgentSpecificMemory() it must be cross-origin isolated, which the dedicated dev server (npm run measure) arranges.
